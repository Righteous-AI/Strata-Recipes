## Cold bench, 2026-11-07 12:27 UTC

Five cold prompts, temperature 0, 256 tokens out, nothing reused, one pass on an idle card. `cached_tokens` was 0 on every row. Client clock.

| Prompt tokens | TTFT | Prefill | Decode |
| --- | --- | --- | --- |
| 8,244 | 1.443 s | 5,712.7 tok/s | 156.6 tok/s |
| 32,820 | 4.531 s | 7,244.0 tok/s | 174.1 tok/s |
| 131,124 | 16.975 s | 7,724.6 tok/s | 174.1 tok/s |
| 196,660 | 25.905 s | 7,591.6 tok/s | 169.8 tok/s |
| 249,908 | 34.607 s | 7,221.3 tok/s | 178.6 tok/s |

The engine's own finished lines on the same five requests read 156.5, 173.7, 173.7, 169.4 and 178.0 tok/s, with expert-cache hits of 91.6, 95.6, 96.1, 95.8 and 96.8%. Those match the client clock to under one percent.

Against the recipe 5 cold bench of 2026-11-03 (4,672 / 7,010 / 7,469 / 7,106 / 6,942 tok/s prefill and 180.0 / 179.6 / 181.2 / 169.4 / 179.4 tok/s decode), prefill from 32k up is level, and the 8,244-token row is about 22% faster. Decode sits 2 to 8 tok/s below that pass on four of five rows. One cold pass a piece is not enough to call that the rebuild: recipe 5's numbers came from a boot that then ran 852 agent requests, and the agent table is the figure that carries weight. This build is running because it is the current tag, with the flags proven on recipe 5.

This build's log line reports the expert-cache hit rate and no draft-acceptance counter, so the acceptance figure for these rows is not available. Recipe 5 holds the last draft-acceptance numbers for this server (67.1% on agent traffic, and 108/170 to 122/171 on its cold bench).

## Same card, different engine

The same five prompts were sent to a TensorFold CUDA server on this card on the same day, at a 262,144 window. It is a different model (a dense 27B in EXL3 6.0 bpw rather than this MoE FP4-Local pack), so read it as two machines rather than a win. The write-up and its numbers are in [TensorFold-Recipes](https://github.com/Righteous-AI/TensorFold-Recipes).
